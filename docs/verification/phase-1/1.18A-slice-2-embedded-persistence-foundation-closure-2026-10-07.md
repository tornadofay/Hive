# Phase 1.18A — Embedded Persistence Profile — Slice 2 Closure Verification

Date: 2026-10-07

## Slice verified

Slice 2 — **Embedded Persistence Foundation** is complete and developer-verified.

The slice establishes the application-owned Embedded SQLite storage foundation behind the backend-neutral persistence boundary while preserving the existing SQL Server/DbUp path. It provides the foundation-only schema/version lifecycle, deterministic migration journal, initialization and inspection behavior, local storage path handling, recovery/locking behavior, cancellation/disposal boundaries, stable provider-neutral persistence errors, and focused regression coverage.

The full `Hive.Tests` suite completed with zero failures. The Slice 2 Embedded foundation tests are part of this suite; no separate focused-only test-run result was supplied.

## Verification history

The first post-implementation developer attempt reported compiler failures in the Slice 2 production/test code, including nullable-flow errors and an invalid catch-filter expression. The same-slice remediation corrected those compile errors and returned the slice to verification pending.

The first broad developer verification after compilation succeeded reported **736 tests with 636 passed and 100 failed**. The failures were systemic across existing Provider Persistence, WorkItem Management, and Hive Persistence integration tests. The common failure was the existing SQL Server migration surface reporting `Hive database migration failed. DbUp did not provide a migration error message.`

The failure was traced to Embedded SQLite migration SQL files being embedded in the same `Hive.Persistence` assembly as the SQL Server DbUp migrations. The existing SQL Server DbUp resource discovery loaded the new Embedded `.sql` resource as well. The SQL Server migrator was corrected to select only resources under `.Migrations.Scripts.`, isolating Embedded migration resources.

The next broad verification reported **736 tests with 725 passed and 11 failed**. The remaining failures were confined to Embedded foundation lifecycle tests: one cancellation-precondition assertion and file-lock cleanup failures. The cancellation test had created its parent directory before asserting that cancellation prevented creation. The test was corrected to use an uncreated path. The Embedded application connection string was also changed to disable SQLite pooling for deterministic file lifecycle.

The next broad verification reported **736 tests with 732 passed and 4 failed**. The remaining failures were three Windows file-lock cleanup failures and one public-error redaction failure. The affected tests were corrected to dispose their additional verification/locking SQLite connections before cleanup, and the corruption error message was made provider-neutral so it no longer exposed the provider name `SQLite`.

The next broad verification reported **736 tests with 733 passed and 3 failed**, all cleanup-time file-lock failures in the rollback, busy-lock, and preexisting-non-Hive-table tests. The remaining raw test-created SQLite connections were then explicitly configured with `Pooling=False`. A mechanical replacement issue was detected and corrected before verification continued.

The final developer verification reported **736/736 passed, 0 failed, 0 skipped**.

## Scope closure

Slice 2 is complete and verified. The verified boundary includes:

- `Microsoft.Data.Sqlite` as the Embedded provider dependency;
- one application-owned Embedded SQLite database path with absolute path normalization and bounded path validation;
- parent-directory creation only when explicitly permitted by configuration;
- deterministic Embedded connection configuration, including foreign keys, durable synchronous mode, and non-pooled application-owned connections;
- non-destructive inspection of missing, invalid, corrupt, future-schema, inconsistent, and foreign-storage states;
- foundation schema/version metadata with a Hive-owned singleton schema-version record;
- deterministic ordered Embedded migration resources and a migration journal;
- contiguous migration-version validation and fail-closed metadata checks;
- transactional migration execution with rollback on failure/cancellation;
- explicit WAL initialization only after preexisting-storage validation;
- bounded busy/locking behavior;
- reopen/recovery behavior for abandoned transactions;
- stable, provider-neutral persistence errors without exposing raw exception messages or provider-specific corruption wording;
- cancellation before storage access;
- deterministic disposal behavior;
- regression protection proving that Embedded migration resources do not enter the SQL Server DbUp migration set;
- focused Slice 2 automated coverage integrated into the full `Hive.Tests` suite.

No later-slice capability was implemented as part of this closure. Full Embedded persistence parity, logical SQL Server ↔ Embedded data migration, Persistence Settings UI/first-run behavior, and cross-backend hardening remain reserved for later 1.18A slices.

No separate build verification result was supplied.
