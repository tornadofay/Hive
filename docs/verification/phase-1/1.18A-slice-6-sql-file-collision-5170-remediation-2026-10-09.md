# Phase 1.18A Slice 6 — SQL Server Error 5170 Diagnostic Remediation

Date: 2026-10-09

## Developer-reported failure

After the prior diagnostic correction, the developer retried Embedded → SQL Server full-data migration and supplied the expanded HiveMessageBox details:

```text
Error code: hive.persistence.migration-sql-failure
SQL Server endpoint: localhost\\MSSQLSERVER01
Database: Hive-Hive.Example.WinForms
SQL error: 5170, state 4, class 16
```

This is the first concrete native SQL failure in the reported endpoint attempt. SQL Server error 5170 means a database file cannot be created because its physical file path already exists. Since the developer had renamed a local database immediately before the failure, a likely explanation is that the renamed database retained physical data/log filenames associated with the old database name, while Hive attempted to create the configured destination database and collided with those files. The owner of the conflicting path has not been directly inspected, so the exact file and owning database remain unconfirmed.

## Same-slice correction

- Added a dedicated 5170 branch to `HiveSqlServerFailureDiagnostics`. It explains the physical-file path collision, notes the possible retained filenames after a database rename, tells the operator to inspect file ownership before retrying, explicitly warns against manual file deletion, and offers a fresh unused destination name or a deliberate SQL Server-managed file relocation as safe next steps.
- Added `5170` regression cases to both `SqlMigrationFailureDiagnostic_ExplainsDatabaseCreationErrorsWithoutSecrets` and `SqlSchemaMigrationFailure_PreservesSafeSqlErrorDetails`. The existing assertions continue to check that connection strings and credentials are omitted.
- The fix is diagnostic-only. It does not change the destination database name, automatically move/delete database files, bypass preflight, or weaken the migration's clean-destination requirement.
- Active Work was changed to `VERIFICATION FAILED / REMEDIATION REQUIRED` before source changes, then returned to `VERIFICATION PENDING` after the bounded correction and record updates.
