## Durable SQL Server failure lesson

The reported SQL Server error **5170** identified a physical database-file path collision when creating a destination. The successful retry used an unused destination name. For future diagnosis, inspect registered file ownership and backups before any SQL-managed relocation; never manually delete a conflicting .mdf or .ldf file. Hive diagnostics must not expose raw connection strings, credentials, or physical paths, and migration must not automatically rename, delete, or relocate files.

## Migration and lifecycle guarantees retained

- SOURCE and DESTINATION configurations are explicit and independent.
- Migration preserves source immutability, verifies the destination before completion, and does not implicitly activate it.
- An active graph must be quiesced before migration; unavailable quiescence fails closed.
- Failure/cancellation and preflight handling must not weaken the clean-destination requirement or expose secrets.
- The developer confirmed first-run and application close/relaunch durability checks multiple times for both Embedded and SQL Server, along with the Example Host Settings / Persistence workflow.
