# 1.21 — V1 Agent Interaction & Application/Form Agents
Objective: extend the Workspace foundation with Agent-directed interaction and application-scoped specialist Agent operation.

Scope:
- Agent mode with explicit Agent selection;
- Agent execution target source configuration with `Auto` or `Favorites`; these are Agent-facing target-source modes and do not add a new internal `ExecutionTargetSelector` mode;
- `Auto` preserves normal behavior when the favorite list is empty: it considers all otherwise eligible ExecutionTargets through the existing authoritative capability-aware execution-target selection/planning boundary;
- when the favorite list contains one or more ExecutionTargets, `Auto` considers only those favorites before invoking the same authoritative capability-aware selection/planning boundary;
- `Favorites` presents only the user's favorite ExecutionTargets for explicit selection, even when the favorite list contains only one target, and pins the chosen exact durable `ExecutionTarget` identity;
- the Agent must never expand a non-empty favorite list to non-favorite targets. `Auto` fails clearly when its non-empty favorite pool contains no qualifying target; `Favorites` has no selectable target when the favorite list is empty and should direct the user to configure favorites;
- a pinned favorite must fail clearly when that exact target becomes unusable rather than silently switching;
- the Agent configuration UI may show provider/model/deployment details as the human-readable label, but the persisted explicit selection is the exact durable `ExecutionTarget` identity; model name alone is never a selection key;
- user commands/objectives submitted to an Agent;
- application-wide Agent support;
- application-scoped role/context such as a Manager Agent;
- form-associated specialized Agents;
- Agent association with bounded host context;
- create/reuse/activate/deactivate Agent instances through the normal Management boundary;
- switching between direct LLM and Agent modes;
- display current Agent/WorkItem/job context;
- ordinary Agent resources with different definitions/context; no new Manager/Invoice framework types;
- no automatic Hive membership or Swarm creation.

V1 Agent model:

```text
Application
    │
    ├── Manager Agent
    ├── Invoice Agent
    ├── Customer Agent
    └── other specialized Agents
```

Verify:
- Agent conversation;
- Agent target-source selection, including Auto and Favorites;
- empty favorite pool behavior: Auto considers all otherwise eligible targets, while Favorites has no selectable target and does not expand to the full catalog;
- non-empty favorite pool behavior: Auto considers favorites only, even when there is only one favorite;
- no fallback from a non-empty favorite pool to non-favorite targets when no qualifying favorite exists;
- selected favorite target remains pinned and fails clearly when it later becomes unusable;
- application-wide Agent;
- specialized form-associated Agent;
- create/reuse/activate/deactivate behavior;
- switching modes;
- independent Agent/runtime state;
- bounded host association;
- authorization remains outside the UI;
- Workspace does not create Hive/Swarm state implicitly.
