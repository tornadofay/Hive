# 1.21 — V1 Agent Interaction & Application/Form Agents
Objective: extend the Workspace foundation with Agent-directed interaction and application-scoped specialist Agent operation.

Scope:
- Agent mode with explicit Agent selection;
- Agent execution configuration with `Auto` or an exact selected `ExecutionTarget`, using the durable Favorite ExecutionTarget pool as the Agent-facing target set;
- `Auto` selects only from the user's favorite ExecutionTargets, then uses the existing authoritative capability-aware execution-target selection/planning boundary;
- explicit target selection presents only the user's favorite ExecutionTargets and pins the chosen exact target; it must fail clearly when that target becomes unusable rather than silently switching;
- an Agent cannot silently expand its target pool to non-favorite ExecutionTargets. When no qualifying favorite exists, `Auto` fails clearly; when the favorite pool is empty, the Agent target-selection surface has no selectable target and must direct the user to configure favorites;
- the Agent configuration UI may show provider/model/deployment details as the human-readable label, but the persisted selection is the exact durable `ExecutionTarget` identity; model name alone is never a selection key;
- user commands/objectives submitted to an Agent;
- application-wide Agent support;
- application-scoped role/context such as a Manager Agent;
- form-associated specialized Agents;
- Agent association with bounded host context;
- create/reuse/activate/deactivate Agent instances through the normal Management boundary;
- switching between direct LLM and Agent modes;
- display current Agent/WorkItem/job context;
- ordinary Agent resources with different definitions/context; no new Manager/Invoice framework types;
- no automatic Hive membership or Swarm creation.

V1 Agent model:

```text
Application
    │
    ├── Manager Agent
    ├── Invoice Agent
    ├── Customer Agent
    └── other specialized Agents
```

Verify:
- Agent conversation;
- Agent selection, including Auto over favorites only and explicit target selection from favorites only;
- empty favorite pool behavior: Auto fails clearly and explicit target selection has no selectable target rather than expanding to the full target catalog;
- no fallback to non-favorite targets when favorites contain no qualifying target;
- selected favorite target remains pinned and fails clearly when it later becomes unusable;
- application-wide Agent;
- specialized form-associated Agent;
- create/reuse/activate/deactivate behavior;
- switching modes;
- independent Agent/runtime state;
- bounded host association;
- authorization remains outside the UI;
- Workspace does not create Hive/Swarm state implicitly.
