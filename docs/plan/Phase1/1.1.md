# 1.1 — Provider / ProviderAccount / ExecutionTarget

## Purpose

Establish the durable provider resource graph used by later provider configuration and execution planning:

Provider
  ↓
ProviderAccount
  ↓
ExecutionTarget

Provider identifies the configured provider/transport identity. ProviderAccount is the credential/account boundary under that provider. ExecutionTarget is the concrete capability-bearing target containing the endpoint and model/deployment identity used for execution.

## Scope

- Define and persist Provider, ProviderAccount, and ExecutionTarget resources.
- Preserve explicit ownership and scope using the Phase 0 resource/identity foundation.
- Apply Hive lifecycle semantics: Active, Suspended, and Retired; retirement preserves durable identity/history rather than physically deleting the resource.
- Represent capability state as Supported, Unsupported, or Unknown.
- Keep capability state separate from provider identity, quota/rate limits, health, cost, and other operational concerns.
- Preserve parent/child lifecycle validation: a ProviderAccount requires an active Provider; an ExecutionTarget requires active Provider and ProviderAccount parents.
- Keep durable uniqueness and malformed-state validation at the Management/persistence boundary.

## Architecture boundary

Provider resources are Hive-owned resources. Persistence belongs in Hive.Persistence; application-facing operations belong in Hive.Management; WinForms only consumes those contracts.

ProviderAccount stores only the reference to credential material. Credential material itself remains behind the existing Secret Store boundary.

This slice establishes the resource model only. Provider/model discovery is a later slice, and discovery evidence must not replace configured ExecutionTarget state.

## Non-goals

No provider transport implementation, automatic model discovery, second provider architecture, credential plaintext storage, or Agent target-selection redesign is introduced here.

## Verify

Verify Provider/ProviderAccount/ExecutionTarget creation, update, retirement/reactivation, ownership/scope, parent dependency validation, duplicate identity conflicts, malformed persisted state, and correct Supported/Unsupported/Unknown capability semantics.
