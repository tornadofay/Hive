# 1.29 — Resource Inventory & Runtime Diagnostics

## Purpose

Provide the V1 operational surface for understanding authoritative Hive resources, active execution state, and bounded diagnostic information without turning diagnostics into another state authority.

## Scope

- Present authoritative inventory for Providers, ProviderAccounts, ExecutionTargets, Agents, RuntimeInstances, Executions, WorkItems, assignments/jobs, operation attempts/receipts, and Review state.
- Expose lifecycle/state information from the owning Management/runtime boundaries.
- Include safe provider/model availability and health metadata where already established by discovery.
- Provide bounded failure diagnostics with correlation/provenance identifiers useful for troubleshooting.
- Preserve ownership/scope filtering and fail-closed access rules.
- Redact secrets and credential material from all inventory and diagnostics.
- Keep inspection read-only unless an explicitly authorized administrative action exists.
- Support reload/reconstruction from durable Hive state rather than relying on diagnostic-only in-memory state.

## Architecture boundary

The inventory is a read-oriented operational view over authoritative Hive.Management and runtime state. It does not become a new persistence model, event source, authorization system, or mutable shadow copy of resources.

## Non-goals

No arbitrary host-database inspection, unrestricted process introspection, credential disclosure, hidden state mutation, or replacement resource registry is introduced.

## Verify

Verify inventory accuracy against authoritative Management state, ownership/scope isolation, lifecycle visibility, runtime/execution inspection, useful typed failure diagnostics, provider/model operational status, secret redaction, and correct state after application restart/reload.
