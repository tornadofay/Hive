# 1.6 — Base Agent Work Protocols

## Purpose

Add only the reusable work mechanisms required by the V1 Base Agent boundary without importing later CognitiveAgent semantics.

## Scope

- Objective lifecycle for a bounded unit of Agent work.
- WorkItem binding and provenance where a Base Agent operates on a durable WorkItem.
- Base memory/work-state storage and retrieval contracts needed by V1 work.
- Question/Answer transport with explicit waiting, completion, timeout, and cancellation semantics.
- Patience / Understanding Gate mechanics for deciding whether sufficient understanding/evidence exists to continue a bounded operation.
- Delegation contracts for requesting work or specialist assistance while preserving ownership, provenance, and authorization.
- Runtime-instance isolation so concurrent incarnations do not leak Objective, Question, memory, or delegation state into one another.
- Deterministic lifecycle transitions and failure reporting through the established Hive result/error boundary.

## Architecture boundary

These are reusable Base Agent work mechanisms, not a cognitive system. They must not autonomously create or revise cognitive Goals or Beliefs, reinterpret experience, select Dreams, generate adaptive Questions, or learn from outcomes.

Simulation/Dream execution and Agent-owned Hive creation remain architecturally possible later but are not prerequisites for this slice.

## Non-goals

No CognitiveAgent state model, persistent cognition, Dream processor, Hive population authority, Swarm resource, or learning/adaptation pipeline is introduced.

## Verify

Verify Objective creation/progression/completion/failure, WorkItem binding/provenance, Question waiting and timeout/cancellation, Understanding Gate behavior, delegation ownership/provenance, concurrent runtime isolation, deterministic failure handling, and cancellation-safe cleanup.
