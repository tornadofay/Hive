# 1.15 — Input Preparation & Routing

## Purpose

Normalize supported V1 input sources into a common prepared-input boundary and route each source through the capability and parsing mechanism required before structured extraction.

## Scope

Initial V1 input paths:

```
Image
  ↓
Vision-capable ExecutionTarget
  ↓
prepared input

Spreadsheet
  ↓
bounded workbook / worksheet / row parsing
  ↓
prepared input
```

- Accept supported input submissions and classify each input item without trusting file naming alone.
- For images, select an eligible vision-capable ExecutionTarget through the existing capability-aware planning boundary.
- For spreadsheets, perform bounded workbook/worksheet/row parsing and preserve source context.
- Keep each input item independently attributable so one malformed or unsupported item does not discard successful items.
- Support one submission producing multiple independent WorkItems where the source naturally contains multiple logical records.
- Enforce file/workbook/row/resource limits and cancellation during preparation.
- Produce one common prepared-input contract consumed by Phase 1.17.
- Preserve input provenance, source identity, correlation, and failure information.

## Architecture boundary

Input preparation is source-specific only until it reaches the common prepared-input boundary. Downstream extraction and validation must not require separate business pipelines for images and spreadsheets.

Hive owns bounded preparation/routing and capability selection; it does not infer arbitrary host business semantics from raw input.

## Non-goals

No structured candidate persistence, business-operation proposal, governed host write, or final business validation is introduced here. Phase 1.17 owns the next common structured-candidate boundary.

## Verify

Verify image routing to eligible vision targets, spreadsheet workbook/worksheet/row handling, multiple logical WorkItems from one submission, bounded resource processing, cancellation, unsupported-input reporting, malformed-input handling, provenance preservation, and failure isolation between input items.
