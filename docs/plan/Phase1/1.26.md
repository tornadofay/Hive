# 1.26 — MAF Sequential V1 Pipeline

## Purpose

Compose the established Phase 1 V1 capabilities into one deterministic single-Agent business workflow using Microsoft Agent Framework Sequential orchestration before introducing application-level concurrent Agent assignment.

## Pipeline

```
Submission
    ↓
WorkItem creation
    ↓
Input preparation / routing
    ↓
Structured extraction / validation
    ↓
Tool / policy / authorization
    ↓
Business proposal
    ↓
Approval / intervention when required
    ↓
Governed host write
    ↓
Receipt / reconciliation
    ↓
Post-write Review
```

## Scope

- Connect the existing V1 phase boundaries in their approved order.
- Use MAF Sequential orchestration where MAF owns the workflow mechanics.
- Preserve Hive-owned WorkItem identity, authorization, provenance, operation identity, receipt, reconciliation, and Review semantics.
- Ensure approval/intervention remains a distinct authorization boundary before consequential host mutation.
- Preserve the distinction between operation success/failure and post-write Review correctness.
- Keep one Agent as the execution participant for this slice.
- Ensure failures and rejected branches terminate at the correct durable boundary without falsely marking later stages complete.
- Preserve cancellation, correlation, resource budgets, and provider/target selection behavior through the full path.

## Non-goals

No application-level multi-Agent concurrency, persistent Hive membership, Swarm, CognitiveAgent behavior, or replacement workflow engine is introduced.

## Architecture boundary

MAF owns Sequential workflow composition and supported execution mechanics. Hive owns identity, policy, authorization, host semantics, durable WorkItem/operation state, receipts, reconciliation, Review, and resource governance.

## Verify

Use deterministic fake provider and fake-host end-to-end coverage for successful execution plus rejected, validation-failed, provider-failed, authorization-failed, host-failed, partial/unknown, cancellation, receipt/reconciliation, and Review branches. Verify the workflow never performs a consequential host write without the required authorization and never treats an unreviewed result as VerifiedCorrect.
