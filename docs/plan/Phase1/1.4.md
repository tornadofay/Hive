# 1.4 — Capability-aware Execution Target Selection

## Purpose

Select an ExecutionTarget using explicit capability requirements while producing diagnostics that explain why a target qualifies, is excluded, or cannot be selected.

## Scope

- Consume Hive capability requirements: Required, Preferred, Optional, and Forbidden.
- Treat capability state as Supported, Unsupported, or Unknown.
- Filter candidates before ranking them for execution.
- Keep Auto, Preferred, and Fixed selection semantics distinct.
- Keep capability selection separate from cost policy, quota/rate limits, health, capacity, modality, and other operational factors.
- Produce bounded, explainable selection diagnostics without exposing credentials or unrelated internal state.

## Architecture boundary

ExecutionTarget selection is an authoritative Hive planning operation. It must use the configured target capability state and later discovery evidence according to the existing authority rules; it must never let model output grant itself capabilities or permissions.

A fixed target remains fixed. If its required capability or operational prerequisites cannot be satisfied, selection fails rather than silently switching to another target.

## Non-goals

No automatic provider/model probing, provider discovery cache, authorization bypass, or new orchestration engine is introduced.

## Verify

Verify supported matches, unsupported exclusion, correct treatment of Unknown for hard requirements, forbidden-capability rejection, no-qualifying-target behavior, fixed-target failure, stable ranking/diagnostics, and separation of capability selection from cost/quota/health concerns.
