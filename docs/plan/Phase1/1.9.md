# 1.9 — First Real Agent Execution

## Purpose

Connect the Base Agent to the Microsoft Agent Framework execution boundary and Hive's provider platform for one real request path with durable lifecycle/correlation evidence.

## Scope

- Start from the existing Base Agent, AgentDefinition, RuntimeInstance, and Execution contracts.
- Resolve an authorized ExecutionTarget through Hive's existing selection boundary.
- Use MAF for execution mechanics where MAF already owns the required behavior.
- Invoke the provider through the shared Hive provider boundary.
- Persist the applicable execution lifecycle evidence using the event/snapshot/outbox foundation.
- Preserve WorkItem/resource ownership, scope, provenance, correlation, and cancellation semantics.

## Architecture boundary

MAF owns execution/workflow mechanics and model-service invocation mechanics where applicable. Hive owns resource identity, provider control-plane state, capability-aware target selection, durable state, authorization boundaries, and Hive-specific operational semantics.

This slice proves the first real Agent execution path; later V1 slices expand it into Workspace interaction, structured extraction, governed business operations, and multi-Agent concurrency.

## Non-goals

No Hive membership, Swarm state, CognitiveAgent behavior, multi-Agent assignment, or complete business-operation pipeline is introduced here.

## Verify

Verify the deterministic fake-provider execution path, successful and failed request handling, cancellation, correlation/causation, durable execution lifecycle state, provider/target resolution, and runtime isolation. Real-provider manual verification may be performed by the developer when appropriate.
