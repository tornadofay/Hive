# 1.20 — V1 Workspace Foundation
Objective: establish the real human-facing Workspace as the common interaction and operational surface over Hive.Management.

Scope:
- Workspace becomes a first-class V1 interaction surface, not only a WorkItem monitor;
- common Workspace shell and conversation/history model;
- direct LLM mode with explicit ExecutionTarget selection; the UI may display provider/model/deployment details for human readability.
- conversation/chat submission and display;
- active execution/runtime context;
- WorkItem/job visibility;
- Workspace restart/reload state handling;
- mode/state presentation boundaries;
- normal Management and authorization boundaries remain authoritative;
- Workspace does not create Hive membership merely because Agents are visible;
- Workspace remains a presentation/control surface, not an authority.

Verify:
- Workspace opens as the normal user-facing interaction surface;
- direct LLM conversation;
- explicit ExecutionTarget selection; the UI may display provider/model/deployment details for human readability;
- active execution/runtime visibility;
- conversation/history behavior;
- WorkItem/job visibility;
- Workspace restart/reload;
- authorization remains outside the UI.

## Slices

Each slice is verified by the developer before the next starts. Visual redesign is its own slice so structure comes first.

1. **Slice 1 — Workspace foundation.** Independent modeless Workspace window and embeddable shell; module contract; Direct LLM and Work Items as modules; public launcher and an `Overview / Getting Started / Workspace` Example page; the Direct LLM ExecutionTarget picker uses saved favorites; Example Host wiring fix. Existing Direct LLM and Work Items operations keep their behavior.
2. **Slice 2 — Chat UX redesign.** Modern conversation layout and message presentation inside the Workspace shell; layout to be defined with the developer before the slice starts.
3. **Slice 3 — Runtime context and WorkItem/job visibility.** Active execution/runtime context and WorkItem/job visibility presented through Workspace modules.
4. **Slice 4 — Restart/reload handling and phase closure.** Workspace restart/reload state handling and verification of the full list above.

Agent mode belongs to Phase 1.21. See `architecture/v1-host-and-management.md` section 5.2 for the window and module boundary.

## Design direction (agreed 2026-10-23)

Hive's UI should combine IDE-style structure with clean, modern card-based content, without letting either dominate:

- compact left sidebar for workspace navigation, conversations, agents, and tools;
- central first-class AI conversation with streaming responses, rich content, and interactive business workflows;
- contextual right panel for agent activity, task details, execution status, and supporting information, collapsible when unnecessary;
- cards only where they add meaning: meaningful grouping, not decorative boxes around every element;
- professional visual design: consistent typography, restrained borders, subtle depth, polished icons, thoughtful spacing, and excellent light and dark themes.

Hive is an AI business workspace, not a code editor. It should inherit desktop IDE efficiency and panel organization without an overly technical appearance, and its content should feel like a carefully designed modern product rather than a generic dashboard made entirely of cards.
