# 1.5 — Base Agent & AgentFactory

## Purpose

Establish the complete useful Base Agent and the factory/runtime boundary used by V1 execution. The Agent generation is fixed when the Agent is created.

## Scope

- Implement the Base Agent identity/lifecycle boundary over AgentDefinition and durable resource identity.
- Define RuntimeInstance and Execution creation so one Agent can have multiple isolated runtime incarnations/executions.
- Implement AgentFactory.Create<TAgent>() against the approved base contracts.
- Make generation selection explicit at creation time.
- Enforce authorization/policy before creating a requested Agent generation.
- Preserve resource ownership, scope, provenance, lifecycle, versioning, and stable identity.
- Keep runtime/execution state separate from persistent Agent identity.
- Ensure creating one runtime from a definition does not implicitly reuse mutable state from another runtime.

## Architecture boundary

The Base Agent is complete and useful without CognitiveAgent behavior. CognitiveAgent is a later additive generation and must not be inferred from task complexity.

The factory owns construction of the requested supported generation; it does not own workflow orchestration. MAF remains the execution/orchestration mechanism where applicable.

## Non-goals

No cognitive beliefs/goals/learning/Dream lifecycle, Hive membership, Swarm, or automatic runtime generation promotion/demotion belongs in this slice.

## Verify

Verify creation of multiple runtimes from one definition, runtime/execution isolation, explicit generation selection, unauthorized generation creation rejection, lifecycle and ownership/scope enforcement, and the absence of hidden cognitive dependencies in Base Agent creation.
