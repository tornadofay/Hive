# 1.10 — Hive.Management Facade

## Purpose

Establish the application-facing Management boundary that exposes authoritative provider/resource operations without forcing hosts or UI code to depend on persistence internals.

## Scope

- Provide management operations for Providers, ProviderAccounts, ExecutionTargets, and AgentDefinitions.
- Perform service-level validation before persistence.
- Enforce ownership, scope, lifecycle, and authorization rules at the Management boundary.
- Translate persistence-layer outcomes into the established Hive result/error taxonomy.
- Keep credential material behind the Secret Store reference boundary.
- Provide operations suitable for both the Hive WinForms UI and future/application host integrations.
- Preserve responsibility direction: UI/hosts consume Management; Management owns application operations; Persistence owns database implementation.

## Architecture boundary

Hive.Management is the application/service boundary for these operations. WinForms must not construct SQL connections, execute SQL directly, or duplicate persistence rules. Host applications likewise consume the public Management contracts rather than bypassing them.

## Non-goals

No direct UI implementation, provider transport implementation, database schema ownership, unrestricted host-business access, or second management facade is introduced.

## Verify

Verify service-level validation, authorization/scope enforcement, lifecycle/dependency validation, persistence integration, structured failure classification, secret-reference handling, and correct behavior for invalid, duplicate, missing, and stale resource operations.
